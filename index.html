How I approach a data problem

I look at the complete data flow, not only the query or the script.

  1. Understand the problem

    What decision or application will use this data? I start there, before touching any tool.

  2. Trace the data flow

    Where the data comes from, what state it is in, and where it needs to end up.

  3. Design the storage

    Choose the database and model that fit how the data will be queried.

  4. Build and check

    Write the pipeline, then test it against the real data, including the awkward records.

  5. Make it maintainable

    Keep the code readable and the flow documented so someone else can pick it up.

Frequently asked questions

What does a data engineer do?

A data engineer builds the systems that move data from where it is created to where it is used. That means extracting data from databases, files and APIs, cleaning and transforming it, and loading it into a structure that analysts, reports and applications can rely on.

What is the difference between ETL and ELT?

In ETL, data is transformed before it is loaded into its destination. In ELT, raw data is loaded first and transformed inside the destination, usually a data warehouse. The right choice depends on data volume, the tools in place and how the data will be used.
